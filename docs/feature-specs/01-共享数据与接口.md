# 共享数据与接口

本文规定跨功能的业务契约。对象及方法名是开发时的统一语义，物理表结构、语言签名和 GUI 框架可在选型后确定。实现应从事务层或服务层保护不变量。

## 对象与写入权

| 对象 | 最小字段 | 主责 |
| --- | --- | --- |
| Scope | scopeId、有效根标识及显示路径、排除规则、policyRevision、状态；全局授权配置另存 scopeEpoch | F02 |
| FileRecord | fileId、当前读授权 scopeId（不再受任何读授权时为空）、currentPath、displayName、format、size、modifiedAt、identityEvidence、contentRevision、availability | F03；F13 更新，确认物理操作后按 F16/F18 更新位置 |
| ExtractionResult | fileId、contentRevision、extractorVersion、status、reasonCode、标题、segments、coverage | F04–F07 |
| RuleSet | ruleSetId、revision、有序规则、匹配条件和类别引用 | F08 |
| Suggestion | suggestionId、fileId、contentRevision、policyRevision、source、配置版本、候选类别、标签建议、依据、reviewReason；AI 可另附主题/用途/摘要 | F08/F09 |
| GroupSuggestion | groupSuggestionId、scopeEpoch、生成配置版本、成员 fileId 及 contentRevision、组名建议、共同主题、代表性段落证据、待核对原因 | F08/F09 |
| Classification | fileId、已确认的 categoryIds 和 tagIds、revision、用户操作时间；引用此前建议可空 | F10 |
| IndexEntry | scopeId、fileId、contentRevision、已发布索引版本、覆盖状态、正文段引用 | F11 |
| Job | jobId、kind、state、phase、进度、失败计数、取消信号 | F01 |
| OperationPlan | planId、revision、操作类型、目标授权、items、确认记录及状态 | F15 |
| OperationItem | itemId、fileId、sourcePath、targetPath、期望身份与内容证据、参与状态、风险及冲突 | F15 |
| OperationJournal | taskId、planId/revision、itemId、阶段、原/目标路径、开始结束时间、结果、reasonCode、恢复证据、syncState | F17；由 F16/F18 追加，保留原执行事实 |

文件在原 scope 内由可靠身份延续管理；授权重叠的发现结果只保留一条对外记录，依从 F02 的授权判定。实体详情至少返回文件当前位置和派生数据版本。文件 ID、类别 ID、计划 ID、任务 ID 是不同类型的内部标识，不能由标题、路径或模型输出替代。日期存可明确解释的时区时间；展示转本地时区。修改时间只表示最后修改。版本无法验证时走失败或待核对，不重新把路径当成授权。

`ExtractionResult.segments` 每项有 `segmentId, text, locator`。定位信息可用页号、段落/表格、文本行等，入库后可用来生成真实命中片段。读取/建索引前后的内容版本要一致。 `coverage` 至少描述是否截断、可定位范围、遗漏原因；未知量用空值，不能填成 100%。 `Suggestion.evidence` 引用同版本的段落或标题；模型生成理由与可核验证据分别保存。

## 状态与错误

- 授权状态 `ACTIVE / REVOKED`。授权失效时立即不可见；后台清理由 F14 追踪。
- 文件可用性 `AVAILABLE / MISSING / INACCESSIBLE / UNVERIFIED`；本次扫描未覆盖且无法确认当前状态时为 UNVERIFIED，不发布无法核验的正文或建议。排除或撤销授权后不再对当前视图可见。文件可用与正文可读独立。
- 提取结果 `EXTRACTED / PARTIAL / EMPTY / UNSUPPORTED / FAILED`。PARTIAL 有可用段及明确限制；EMPTY 无可用段；FAILED 与 UNSUPPORTED 不能进入正文索引。等待和分析中用任务状态表示。
- 索引状态 `NOT_INDEXED / BUILDING / READY / PARTIAL / STALE / FAILED`。READY/PARTIAL 仅针对已提交的当前版本。
- 通用任务 `QUEUED → RUNNING → COMPLETED | PARTIAL | CANCELLED | FAILED`；CANCELLED 若已有可核对结果，在任务摘要报告实际数量。
- 计划状态 `DRAFT → VALIDATED → CONFIRMED → EXECUTING → CLOSED`，另有 `CANCELLED / INVALIDATED`。终止尝试需新修订或新计划，不能复用旧确认。`VALIDATED`只描述预检，不能执行。
- 操作项阶段 `PENDING / INTENT_RECORDED / MUTATING / SUCCEEDED / SKIPPED / FAILED / UNKNOWN`；若存在不确定磁盘变更使用 UNKNOWN，不得普通重试。撤销通过独立任务记录相同阶段，原任务成功事实保留。
- 操作同步状态独立于磁盘结果。磁盘成功使操作项进入 SUCCEEDED，管理记录未追上时为 `syncState=PENDING_SYNC`，完成后为 `SYNCED`。磁盘结果尚未核实时不得标 SUCCEEDED。同步只能补管理记录。
- 通用错误 `{code, message, retryable, relevantIds}`。稳定错误码使用 `OUT_OF_SCOPE / EXCLUDED / STALE_REVISION / UNREADABLE / ENCRYPTED / MALFORMED / LIMIT_EXCEEDED / NO_TEXT / UNSUPPORTED_FORMAT / MODEL_UNAVAILABLE / MODEL_OUTPUT_INVALID / CONFLICT / NOT_CONFIRMED / INTERRUPTED / STATE_UNKNOWN`，详细情形可增加子码并记录来源。对用户显示可理解文案，避免泄露模型输入和堆栈。

## 服务接口与权限

| 服务 | 输入 → 输出 | 可写范围 |
| --- | --- | --- |
| 授权服务 | 明确选择的根与规则 → Scope；按快照校验路径及版本 | 授权与排除记录 |
| 扫描服务 | 有效 scopeId、policyRevision、取消信号 → FileRecord 清单和任务报告 | 管理记录 |
| 提取服务 | 扫描确认的 fileId、只读输入、版本/限额 → ExtractionResult | 无原文件写操作；只返回结果 |
| 分析服务 | 当前 ExtractionResult、获准资料引用、配置版本 → Suggestion | 待审建议 |
| 分类服务 | 文件和分类 ID、用户提交、期望 revision → Classification | 分类体系、规则选择和关联 |
| 索引与搜索 | 提交当前提取结果；QuerySpec → SearchResult[] 与覆盖信息 | 权威数据只读，索引可重建 |
| 计划服务 | 已管理文件、用户目标及调整 → 固定计划与用户确认 | 计划及确认记录 |
| 执行与撤销 | planId/revision 与有效确认；历史记录生成撤销计划 → 逐项结果 | 指定磁盘位置及操作记录 |

`QuerySpec` 至少含 scopeIds、terms、可选 categoryIds/tagIds/formats/dateFilter、排序及分页。结果项至少含 fileId、位置、判定时的内容版本、命中字段与真实定位、索引覆盖和可用性。过滤范围由服务重新求当前授权交集。建议、搜索、分类与默认扫描接口均不依赖操作执行器。

## 跨功能提交规则

| 变更 | 权威记录 | 同步行为 |
| --- | --- | --- |
| 排除规则或授权有变 | Scope | 提升 scopeEpoch，读侧立刻按有效策略筛选。尚未提交的旧授权快照任务失效。先保护可见性，再重新扫描或异步清理。重叠范围也重新计算判定。 |
| 正文版本变化 | FileRecord | 旧正文索引和内容建议失效。人工确认分类保持。重提取后仅发布与当前版本一致的结果。 |
| 用户改标签或归属 | Classification | 立即更新结构化筛选。正文版本和物理位置保持。 |
| 可信改名或移动 | FileRecord、OperationJournal（应用执行时） | 沿用 fileId，更新名称、位置与有效授权归属。对位置敏感的建议重新判断。目标没有读取授权时仅保留执行所需管理信息。 |
| 磁盘写入已发生、派生数据未同步 | OperationJournal | 标记待同步并隐藏不能确认的旧路径结果。根据确认的磁盘事实修复管理记录，禁止通过重跑移动实现补偿。 |

读取链路携带 `scopeEpoch + scopeId + policyRevision + fileId + contentRevision`，在打开文件、发送模型输入和发布派生结果前核对有效策略与版本。规则结果额外携带 RuleSet 版本，模型结果额外携带模型/分析配置版本。GroupSuggestion 的证据使用每份成员的 fileId、contentRevision、segmentId，任一成员不再有效时整组建议失效，人工确认分类保持。操作链路只消费由计划服务保存的 `planId + revision` 与一次性确认记录，并按当前政策复核。UI 传入的状态描述不替代服务验证。

## 示例

文档 `f42` 的 PDF 第 3 页解析为 `segmentId=page3-1`。第 4 页无有效文字，提取状态为 PARTIAL。搜索第 3 页的词可以返回真实命中并提示覆盖不完整。AI 建议如引用第 4 页不存在的片段，该引用不能作为依据。用户确认标签后刷新索引，确认关系与建议仍各自保留。若后续撤销目录授权，所有关联内容立即从搜索和模型输入中消失，原文件保留在磁盘。
