# 开发接入与系统验收

## 按功能文档生成代码

开发任务给出功能编号、适用阶段与测试环境。每次读目标功能文档、全局边界、共享契约，再按依赖编号读取相关文档。基于正式工程选择代码位置。尚无依赖实现时，可以用契约级测试替身验证边界，但不能把替身作为交付行为。功能文档中的输入/输出是应用层接口；内部库或 GUI 技术由正式选型决定。

开发提交应能对应每条验收项，区分自动验证、Windows 实机验证、样本质量验证。测试使用隔离目录、预制文档和本地假模型，不读取私人资料。开放物理操作前用测试副本记录源/目标路径、字节哈希和历史；用故障注入覆盖中断点，不测试用户唯一副本。

## 推荐集成顺序

1. F01/F02/F03/F14 建立只读工作台、授权和持久化基础；F04–F07 按统一结果契约接入四种文档。
2. F11/F12/F13 完成原位检索与手动刷新；F08/F10 完成规则建议、人工确认和多标签。F11 初始版本可只消费文件与正文，F10 完成后补分类筛选。
3. F09 与 F08 使用相同文件版本、测试样本和人工标注验证效果。摘要、候选分组和标签可单独决定发布。
4. F15–F18 一起集成，在测试副本中核对全过程和异常。F19 先验证桌面分发骨架，再验收最终包中实际开放的能力。
5. F20–F25 仅在明确确定范围后安排。

## 待决清单

- Windows 最低支持版本、架构、发布形式及应用数据位置的具体目录名。
- 桌面框架、存储/索引组件与解析器版本；允许 Markdown 的具体方言、支持的 TXT 编码、文件大小/页数/解压预算和耗时上限。规格里的确定性策略是建议基线，发布时须以可测上限记录。
- 默认管理入口、分类维度和方案选择顺序；首版规则样式、中文词法检索方案、模型选型、模型输入与输出上限、启用的 AI 子功能。
- 真实操作支持的 Windows 文件系统、卷和目录范围；执行原语及中断恢复方案。跨卷与重解析路径默认关闭，属于保守的工程基线。若要放开，需要单独验证。
- 原始正文/派生数据保存期限、清理与日志保留策略；发布前明确到用户可读说明。
- F20/F21 所述能力启用前，需明确其与正式 AI 职责边界的一致性；具体模型、阈值、排行榜或向量库均未定。

## 端到端验收

| 用例 | 操作及通过标准 |
| --- | --- |
| E01 桌面基础 | Windows 普通账户启动独立窗口。未安装模型时，四格式基础处理、人工分类和搜索仍可用。重启恢复配置和已确认关系。 |
| E02 授权与解析 | 目录含四种有效样本、私人子目录、可构造的链接、加密/扫描/混合 PDF。验证未授权内容未打开且不进入索引或模型输入；逐类校验可用结果及覆盖状态。 |
| E03 原位管理 | 将一份文件关联两个类别和三个不同标签，修改系统建议，重扫重启后保留确认结果。前后原文件路径、哈希和数量一致。 |
| E04 检索与更新 | 搜索只在文末出现的词，展示实际命中位置。改正文、改名及撤销授权后分别刷新；结果不返回失效正文或越界内容。 |
| E05 AI 降级 | 同批测试正常建议、超时、无效字段、正文含指令。失败项目可人工处理，模型不生成可执行动作，其余基础功能照常。 |
| E06 写权限 | 预览、拒绝、篡改计划、目标同名和确认后源变化均不能写对应的原文件。确认后的有效项移动/改名并更新路径。 |
| E07 历史与恢复 | 分别模拟单项失败、日志与磁盘不同步、重启中断、恢复位置占用、目标内容改动。逐项结果真实，不误报已完成，不覆盖。 |
| E08 清理权限 | 撤销范围授权使结果立即不可见。按用户选择清理派生数据，原目录中每个文件的路径和哈希不变。 |

## 最小样本集

- 授权测试使用两个相似命名的根目录、一个重叠子范围、一个排除子目录，以及指向范围外的目录链接或 Windows 重解析点样本。读取器用可观测探针记录哪些对象真正被打开。
- 四格式各提供至少一个可查询的中文样本。TXT 加异常编码和空白样本，MD 加外部链接和本地引用，DOCX 加交错段落/表格、外部关系和损坏样本，PDF 加纯文字、扫描、混合、加密及损坏样本。每种格式设置可注入的低预算来测试截断。
- 索引样本把测试词分别放在标题、正文开头和正文末尾。配两份字节相同但身份不同的文件，以及一份同名但内容不同的文件。外部编辑用新旧内容标记验证索引切换。
- AI 样本注入无效类别、伪造证据、超时及晚到响应。受测模型仅能看见本次授权输入，记录请求内容的是测试探针，生产日志仍遵循 F14。
- 写入样本以互相隔离的授权目录保存独立副本。覆盖拒绝确认、确认后编辑、同名、路径变化、磁盘提交中断和撤销占用。每项记录磁盘状态和任务状态，检查两者准确对应。

## AI 对照评价

使用相同任务和整理偏好，对比纯本地规则与本地规则加 AI。建模或调试样本与最终验收样本分开，覆盖标题清楚、文件名含糊、跨主题、模板相似、短文档和解析失败。记录类别/标签匹配、分组合并拆分次数、依据有效性、摘要错误与遗漏、人工修改量、总耗时、模型与硬件。搜索评价对基础关键词任务记录目标是否进入前三及无命中表现。报告写清样本数与条件，验收阈值在试测后确定，不能把历史 Demo 结果当本项目效果。
