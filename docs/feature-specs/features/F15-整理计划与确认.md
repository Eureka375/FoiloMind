## 入口与预览

用户显式进入“物理整理”，选择参与文件、目标根以及目标相对位置。可从已确认分类生成建议目录，再人工修改。一项文件只有一个目标；多类别没有唯一目标时等待用户选定。用户能从预览逐项看到文件名、来源、目标、新旧名称、纳入状态和冲突原因。生成、编辑、校验、取消计划期间不得创建原目录内的文件或目录。

## 固定计划与授权

- 输入是 fileId 列表和用户选择的动作，目标根由用户显式授权。读取范围不会产生写许可；确认界面展示即将修改的源和目标。路径由程序按 Windows 规则构造并检查，不接受模型输出的路径或操作。
- 预检检查当前来源、身份、目标权限、可写性、占用和批内重复目标；发现冲突须跳过或改名重新校验，不能在确认后静默换目标。未知或受保护项不能参与。
- 编辑推进 planRevision，旧确认立刻失效。正向确认必须绑定 planId/revision、操作种类、参与项、源与唯一目标、身份/版本证据及授权边界；以服务生成和持久化的记录为准，不能由 UI 自报“已确认”。
- 用户拒绝、取消或没有有效项时不交给执行器。执行服务按冻结版本原子认领确认，防止重复点击或多个任务消费；权限撤回或计划过期使相关项拒绝。另一次执行尝试需重新建立并确认计划。
- 独立的改名计划沿用同样规则，目标目录与源目录相同，扩展名保持。撤销由 F18 生成独立反向计划，经同一确认校验。

## 验收

- F15-AC1 生成计划、手动改名、取消和否定确认后，目录结构、文件哈希、数量一致。
- F15-AC2 修改已确认计划任意参与项或目标后旧确认无效；直接调用、伪造确认和重放被服务拒绝。
- F15-AC3 多标签文件只出现一个待确认目标，批内冲突显示原因。来源/目标明确，跳过项不执行。
