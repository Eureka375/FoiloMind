## 日志契约和可见内容

历史页按任务展示时间、动作、范围及逐项原路径/目标、开始结束时间、结果和原因。变更前持久化意图与恢复证据；日志不可用时不得开始变更。成功、失败、跳过、待核对分别呈现。撤销写独立事件并关联原任务，保留原操作事实。路径访问遵循当前授权，普通日志不记正文。

## 中断处理

- 重启时查找停留在意图或执行中的项，标记待核对。仅按仍有效授权检查两处状态与身份/内容证据，不能因为文件存在就认定操作成功。
- 只有明确证明尚未变更、或变更已完成且唯一对象可确认时更新状态与索引。源/目标都存在、都不存在、证据不足或对象变化时保持待核对，展示可核实事实；不自动删副本、不自动续跑，也不借旧确认重试。
- 磁盘已经成功但索引更新失败时，操作项为 SUCCEEDED，独立标记 PENDING_SYNC，显示“文件已变更，管理记录待同步”；仅同步元数据不构成再次执行。日志结果本身未提交时先核对磁盘，核实后再写入该结果。恢复流程幂等，重复打开历史不能产生更多文件变更。
- 清理历史前说明会失去哪些撤销证据。未核对项不得被普通清理周期自动删除。

| 核对时观察到的状态 | 处理 |
| --- | --- |
| 源在原处且身份、内容与意图一致，有证据确认本任务未变更目标 | 记录中断且未执行。再次执行需重新确认。 |
| 源已离开原位置，目标唯一且身份与任务证据一致 | 记录磁盘已变更，补传位置更新。若补传失败继续标明待同步。 |
| 两处均有对象、两处均缺失，或任一对象、范围、版本无法可靠核验 | 维持 UNKNOWN。提示用户人工核对，不删除、不覆盖、不重试原操作。 |

## 验收

- F17-AC1 在记录意图后、磁盘变更后及提交索引前分别故障注入，重启显示实际或待核对状态。
- F17-AC2 无法写入操作日志时拒绝修改原件；异常状态不会被批量归为成功或可普通重试。
- F17-AC3 反复核对历史不会再次移动，主动限制访问后不会显示或打开越权正文。
