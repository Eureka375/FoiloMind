## 流程与更新规则

用户按当前范围触发刷新。读取当前授权版本，枚举有效文件，与已有 FileRecord 比对。P0 可重新枚举整个范围，但要保留已确认关系和有效记录；P1 优化只处理变化，不改变行为。解析与分析可分别排队，任务回写时共同核对授权、内容及配置版本。

- 新增记录开始提取和建索引。
- 可靠证据表明字节内容变化时，推进内容版本，旧正文和建议标记过期，重新解析。大小和修改时间只能作为筛选信号，不能单独证明内容不变。
- 身份可靠且仅位置变动时更新路径与名称；基于名称/路径的建议可失效，不默认重提正文。身份不明时不把人工标签自动迁移到新文件。
- 完整枚举后，未发现的旧文件才标记 MISSING；权限或 I/O 问题标为 INACCESSIBLE；本次任务未覆盖且无法确认当前状态标为 UNVERIFIED。后两种均不能误判删除，也不返回需要重新核验的正文。
- 排除/授权变化先阻止新读取和旧结果发布，再按 F14 清理数据。人工类别变动只处理筛选关系。
- 进度与结果区分新增、更新、失效、不可访问和跳过数。并发刷新对同范围合并或按版本拒绝旧提交；中断保留可用进度，可用户手动重试。

## 验收

- F13-AC1 新增、正文变化、外部删除分别得到新记录、新命中及失效状态。
- F13-AC2 可验证的同卷外部改名不丢标签或产生重复项；无法验证的替换文件不继承标签。
- F13-AC3 中途取消、权限拒绝和范围变化都不会把未覆盖文件标删除，也不发布迟到旧正文。
