# 从混杂资料中自动识别课程

## 使用步骤

1. 在项目虚拟环境中运行 `python -m pip install -r requirements.txt`，再启动 `python launch.pyw`。
2. 打开“AI 分析与审核”，点击“选择文件夹并按课程分类”。新来源使用“文件库”里的递归和排除设置。已导入的来源使用原有读取范围。确认后，程序从所选范围提取 TXT、MD、DOCX 和文字型 PDF。
3. 按课程展开文件，在文件项查看原文片段。选中一份文件或一整门课，点击“修改课程分类”。可在下拉列表里选择课程，也可以输入自己的课程名称。留空可转入待确认。
4. 选中要保存的文件或课程，勾选“主分类”并点击“接受选中项”。草案可通过“历史方案”重新打开。确认只更新资料库里的课程归属。需要在磁盘上移动时，可另外通过“整理与历史”建立移动计划。

## 分类范围

学生入口每份文档最多建议一门课。内置计算机网络、数据库、编译原理、Java 后端、数据结构、操作系统、计算机组成原理、软件工程、高等数学、线性代数、概率论与数理统计、大学英语。用户打开文件夹即可使用。

程序只从采样正文匹配课程线索。同一概念的别名和重复出现只计一次。分数太低、两门课程的分数太接近、缺少正文或没有找到匹配课程时，文件进入待确认。确认课程时保留已记录的用途、标签和拟用名称。

## 算法与后续扩展

- `foliomind/subjects.py` 维护课程表和正文匹配。每份文档复用原有正文抽样，最多均匀抽取十个已有段落、行或页面。长片段取前后部分，审核页保留覆盖状态和可定位的原文片段。一批最多生成 500 份文档的分类草案。
- 原有 TF-IDF、MiniLM、HDBSCAN 和关键词组名生成保留在 `foliomind/discovery.py`。细主题分组通过原有服务和独立[分类实验](../../experiments/document_classification/README.md)验证。后续可作为课程内可选细分，或作为课程表之外的主题发现方式。
- 两套算法共用导入、草案、历史和审核。后续扩充课程表或引入新的课程分类模型，可以复用这套流程。

## 验收

可用 `python -m unittest discover -s tests -p "test_subjects.py" -v` 运行课程分类服务测试。桌面测试验证从选文件夹到确认保存，会直接展示「课程 / 文件」。新样本测试覆盖同一课程不同知识点、模糊或误导性文件名、未覆盖学科、跨课程，以及只写入课程归属。

在同一批 40 份已知合成资料上，学生版建议 4 门课程。36 份单课程文档里有 34 份建议符合参考归属，2 份待确认。4 份跨课程文档里，2 份建议落在可接受课程之一，2 份待确认。原文件的 40 个 SHA-256 均保持一致。这批资料的主题已知，结果用于核对产品粒度，真实资料上的覆盖与审核量仍需验证。

原细主题方案在同批资料上的历史结果为 10 个 TF-IDF 候选组、15 份待确认，以及 10 个 MiniLM 候选组、13 份待确认。它的组名以局部主题为主。同一门课包含多个候选组的情况由学生入口的课程表解决。
