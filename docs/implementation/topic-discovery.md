# 从混杂资料中自动发现分组

## 使用步骤

1. 在项目虚拟环境中运行 `python -m pip install -r requirements.txt`，再启动 `python launch.pyw`。
2. 打开“AI 分析与审核”，点击“选择文件夹并发现分组”。新来源使用“文件库”里的递归和排除设置。已导入的来源使用原有读取范围。确认后，程序从所选范围提取 TXT、MD、DOCX 和文字型 PDF。
3. 展开分组，在文件项查看原文片段。选中一份文件或一整个分组，点击“修改分组”。输入已有组名可把所选文件归入该组，清空名称可转入待确认。修改前可核对差异。
4. 选中要保存的文件或分组，勾选“主分类”并点击“接受选中项”。只接受有归属或已编辑的项目。草案可通过“历史方案”重新打开。确认主分类只更新资料库。需要在磁盘上移动时，可另外通过“整理与历史”建立移动计划。

默认使用关键词。要试语义向量，先运行 `python -m pip install -r requirements-local-model.txt`。勾选“使用本地语义模型”后，在选择资料文件夹之后选择包含 `model.safetensors` 的完整 Sentence Transformer 模型目录，例如分类实验已准备好的 multilingual MiniLM。首次准备权重的步骤见 [分类实验说明](../../experiments/document_classification/README.md)。应用在本机加载模型并进行 CPU 推理。默认打包环境只需基础依赖，使用语义模型时可从安装了扩展依赖的源码环境启动。

## 算法与后续扩展

- `foliomind/discovery.py` 分开执行正文抽样、向量生成、分组和取名。每份文档最多均匀抽取十个已有段落、行或页面。长片段取前后部分，审核页保留覆盖状态和可定位的原文片段。一批最多聚类 500 份。
- 默认用中文相邻双字和英文词构建 TF-IDF。可选模式按模型实际 token 长度切分采样文本，合并为文档向量。两种方式都用余弦距离和 HDBSCAN 生成候选组。类别数由数据决定，缺少相似资料的文件留待确认。
- 组名来自组内多份文档共有、在其他组相对少见的词，中文用 Jieba 分词。组名可能偏向局部主题。已有资料库 `Proposal` 与审核界面负责保存、编辑、历史和确认。后续可独立改进向量、组名生成和分组粒度，并继续使用同一套审核流程。现有的云端分析与移动计划也可从各自入口使用。

## 验收

针对发现链路验证选择目录、范围排除、保留原件、分组命名和人工确认。可用 `python -m unittest discover -s tests -p "test_discovery.py" -v` 运行服务测试。现有桌面测试覆盖从文件夹选择到点击确认后写入分类的流程。评估分组质量时记录组数、需要合并或拆分的组数、待确认数和人工审核时间。

在 Linux Tk 桌面环境完成 29 项应用测试。Windows 专用的四项磁盘改名测试及新打包产物需要在 Windows 上复验。在另建的临时资料库中，以同一批 40 份合成资料运行两种发现方式。TF-IDF 生成 10 个建议组、15 份待确认，实跑 multilingual MiniLM 生成 10 个建议组、13 份待确认。两者都将部分人工参考课程拆成多个小组，也会将少量不同参考课程归到一起。该批用于验证从文档到草案的流程。正式使用还需要在真实资料中验证组名和人工调整量。
